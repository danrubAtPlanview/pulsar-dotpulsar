## wp10-g4b-dlq-chunk: dead letter, negative ack and chunking rows (merged)

Commits: `Port the missing dead letter topic tests`, `Port the missing small broker chunking tests`, `Connect the dead letter test consumers one by one`, `Port the missing chunking tests`, `Drop the received messages when redelivering all` (production fix), `Port the concurrent redeliver and receive test`. Build: 0 errors, the 4 pre-existing warnings (Debug and Release); Debug unit 2118 passed, 11 skipped.

**Production bug found and fixed (`Drop the received messages when redelivering all`, with a Fixed line in the CHANGELOG):** `Consumer<T>.RedeliverUnacknowledgedMessages()` on a partitioned or multi-topic consumer left the message that a sub consumer had already returned to the `Consumer` but that the application had not yet received (`_receiveTasks[i]` completed). After the redelivery the application got that message twice. Java's `MultiTopicsConsumerImpl` clears its incoming queue there. The fix (`DropReceivedMessages`) replaces a completed receive task by the never-ending task before the sub consumers redeliver; a pending receive stays pending, and `Receive` starts a new receive when it needs one. Regression test: the ported `testFailoverConsumerBatchCumulateAck` (failed 3 of 3 with `count 10, expected 9` without the fix, passed 3 of 3 with it). There is no unit test (a `Consumer<T>` with fake sub consumers is not practical). Residual race, harmless: a task that completes between the status check and the exchange is either dropped (the broker redelivers it) or returned to the application just before the redelivery.
